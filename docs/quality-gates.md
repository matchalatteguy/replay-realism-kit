# Report quality gates

Gates check local report structure, declared causal timing, and internal accounting. They cannot authenticate the source stream or validate a venue's matching behavior.

| Gate | Requirement |
| --- | --- |
| `report-shape` | Supported v1 schema, typed objects and rows, finite numeric values. |
| `report-consistency` | Decision-result counts, positive-fill states, fee totals, filled notional, configured fees, and signed markout arithmetic agree. |
| `assumption-profile` | Reconstructed profile has positive latency, tolerance at most 5000 ms, and required future markouts; its label agrees. |
| `fee-model` | Complete named finite non-negative fee rates; both-zero rates have the explicit flag. |
| `sample-count` | At least one decision result, including unfilled decisions. This is fixture completeness, with no statistical adequacy claim. |
| `future-markout` | Positive fills have usable future midpoint/edge/horizon fields when required. |
| `stale-book` | No decision reports the stale-book rejection. |
| `execution-evidence` | Generated configuration and trace quantities, available source volume, directional price limits, maker limit/slippage, causal book/trade timing, expiry, and bounded observation timing agree. |
| `maker-observation` | Attempted makers fill or have evidence through exclusive expiry; unfinished truncated windows fail. |
| `arrival-book` | No taker lacks a causally known matching quote. This failure is emitted when applicable. |

The final three checks apply when the report includes simulation configuration (generated by 0.3). Legacy v1 reports without it retain structural and arithmetic checks. Missing markouts and incomplete maker windows are visible in comparison results; they never become a zero-valued aggregate edge.

`reviewable` is an assumption heuristic. Zero-latency comparisons still run and retain their results, but fail this built-in policy. A fully observed maker can legitimately have no fill. Data completeness needs a separately chosen minimum-fill/coverage policy appropriate to the consumer.

## CLI policy

```bash
uv run replay-realism simulate \
  --events examples/synthetic-book/events.csv \
  --assumptions examples/synthetic-book/assumptions.yaml \
  --json-out reports/replay.json
uv run replay-realism gate --report reports/replay.json --md-out reports/review.md
```

`simulate` writes the report, and `gate` applies checks. `compare` runs checks for every scenario and writes JSON/CSV/Markdown even if any gate fails. Exit codes: `0` for successful checks, `1` for failed gates, `2` for malformed or unreadable input. Report-shape failures can still produce a Markdown review. Output paths must be distinct and must not replace inputs.

Results contain `name`, `severity`, `reason_code`, and `message`. Use the reason code in automation. Decimal arithmetic uses an isolated 28-digit context with relative tolerance `1e-24` for rounded weighted-average prices. There is no absolute zero floor; overflow or underflow fails consistency checks.

Trace arithmetic can detect internally impossible fills or altered limits. Source authenticity, missing upstream messages, inferred queue priority, shared liquidity, sufficient sample size, and actual execution performance require independent evidence outside this report.
