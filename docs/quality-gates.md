# Report quality gates

Gates check a local report's structure and internal consistency. They do not certify real execution or statistical evidence.

## Built-in policy

| Gate | Requirement |
| --- | --- |
| `report-shape` | Supported v1 schema; object assumptions and summary; list of typed fill rows with finite values. |
| `report-consistency` | `fill_count`, `filled_count`, and `fee_total` agree with rows. Counts are actual integers, not strings, floats, or booleans. Positive-fill states agree with reasons and remaining size; notional, configured fees, and signed markout arithmetic agree. |
| `assumption-profile` | Reconstructed typed profile has positive latency, tolerance at most 5000 ms, and required future markouts; serialized safety label agrees. |
| `fee-model` | Complete named finite non-negative fee rates; both-zero rates require the explicit-zero flag. |
| `sample-count` | At least one decision result exists, including unfilled decisions. This is only a fixture completeness check. |
| `future-markout` | Each positive filled size has an `ok` markout with positive midpoint, finite edge, and positive integer horizon. |
| `stale-book` | No decision reports the `stale-book` rejection reason. |

Malformed input produces failure gates rather than exceptions. The `gate` command exits `1` for a report that fails these rules and `2` when its JSON cannot be parsed or the file cannot be read. `--md-out` can produce a readable review even when the report shape is invalid.

Each result contains `name`, `severity`, `reason_code`, and `message`. Current policy emits `pass` and `fail`; `warn` is available for extensions. Use reason codes for automation. Human messages can change.

## Run in a pipeline

```bash
uv run replay-realism simulate \
  --events examples/synthetic-book/events.csv \
  --assumptions examples/synthetic-book/assumptions.yaml \
  --json-out reports/replay.json
uv run replay-realism gate --report reports/replay.json --md-out reports/review.md
```

Reports generated by `simulate_replay` anchor markouts to actual execution timestamps. A gate receiving an arbitrary JSON document cannot verify source authenticity, match a fill to a source event, or independently reconstruct future timing from only a midpoint and horizon. Those require source-event review. Passing all gates also says nothing about profitability, real fill probability, venue compatibility, or sufficient sample size for an inference.

Arithmetic comparisons use a 28-digit Decimal context and relative tolerance `1e-24` to accommodate rounded weighted-average prices. There is no absolute tolerance floor that would treat an arbitrary tiny non-zero fee as zero. Arithmetic overflow fails the consistency gate.
